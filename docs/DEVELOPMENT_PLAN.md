# 개발 계획

1. 데이터 감사 결과와 미해결 질문을 확인한다.
2. Supabase 스키마·RLS·마이그레이션을 사용자 승인 후 설계한다.
3. 업체 검색과 필터 화면을 구현한다.
4. 지도점검 직접 등록과 규칙 기반 참고 요약을 구현한다.
5. PDF 텍스트 추출·담당자 검토 흐름을 구현한다.
6. 처분 후보 검토 및 내보내기를 구현한다.

각 단계는 사용자 확인 후 진행하고, 입력 원본은 계속 보존한다.

## 현재 완료된 준비 단계

- 로컬 CSV 조회 MVP와 기존 테스트를 유지한다.
- Supabase용 테이블·제약·인덱스 SQL 초안을 준비한다.
- 기본 동작이 DB 쓰기를 하지 않는 dry-run 가져오기 스크립트를 준비한다.
- `DATA_BACKEND=local`을 기본값으로 유지하고 저장소 계층만 분리한다.

## 다음 승인 단계

1. 사용자가 SQL과 dry-run 결과를 검토한다.
2. 사용자가 Supabase 프로젝트를 만들고 SQL을 직접 적용한다.
3. 운영 인증·권한 범위를 결정하고 RLS 정책을 추가·검증한다.
4. 사용자 명시 승인 후에만 실제 초기 데이터 가져오기를 수행한다.
5. 건수와 외래키를 재검증한 후 `DATA_BACKEND=supabase` 조회 전환을 별도 단계로 진행한다.
